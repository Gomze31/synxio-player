# Synxio 6.0 — Étape 4 : Recherche dans les Réglages — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un champ « Rechercher un réglage » en tête des Réglages ; un résultat ouvre la sous-page, défile jusqu'au groupe et le surligne.

**Architecture:** Catalogue statique `ui/screens/settings/SettingsCatalog.kt` : groupes ordonnés par sous-menu (clés des `group(index, key, title)` de `SettingsScreen.kt`) et entrées `(titre, sous-menu, groupe, mots-clés)`. Recherche floue `SettingsSearch.search` (normalisation accents/casse via `normalizeForSearch`, tous les mots doivent correspondre, score titre > mot-clé > groupe). Le saut passe par l'état existant `currentSubMenu` plus `pendingTarget` ; la sous-page reçoit un `LazyListState` et défile vers `1 + indice du groupe` (l'en-tête est l'élément 0 ; `SYSTEM_AND_ABOUT` a l'élément `updates` avant ses groupes). Le surlignage est un état de fichier `highlightedGroup` lu par `group()` → `SettingsGroup(highlighted)`, bordure accent animée 1,8 s. Un test JVM relit le source de `SettingsScreen.kt` et vérifie que chaque titre statique des sous-pages est au catalogue.

**Écart assumé avec la spec §4 :** la granularité est le groupe, pas la ligne (pas de paramètre `id` ajouté aux 85 composables) ; le découpage de `SettingsScreen.kt` en fichiers par sous-menu est reporté (aucun bénéfice utilisateur, risque de régression visuelle, contexte de session).

**Spec:** `docs/superpowers/specs/2026-11-24-synxio-6.0-flow-design.md` §4 ; prérequis : étape 3 livrée (`v5.13.0`).
