# Synxio 6.0 — Étape 3 : Démarrage et mémoire — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Premier écran plus rapide (baseline profile), pochettes jamais décodées en pleine taille pour en tirer des couleurs, décodage PCM sans boxing.

**Architecture:** Constat (repérage du 25 novembre) : un décodeur sous-échantillonné partagé existe déjà, `playback/art/ArtBitmaps.decode(context, uri, target)`, utilisé par les widgets, la montre, la mosaïque et `ArtworkProvider` ; `ui/theme/ArtworkColors.kt` décode déjà en 128 px via Coil ; `ArtworkColorRepository.getColors` n'a aucun appelant (seul `clearCache` l'est, depuis `SettingsViewModel`). L'unification se réduit donc à : `ShareCardRepository.loadArtwork` passe par `ArtBitmaps.decode` ; le pipeline mort de `ArtworkColorRepository` est supprimé (la table `artwork_colors` reste, vidée par le réglage existant). `PcmDecoder` accumule dans un `PcmBuffer` (`ShortArray` à croissance géométrique, repli mono intégré), testé en JVM. `profileinstaller` et un `baseline-prof.txt` manuel (règles `HSPL` par paquets) entrent dans `:app`.

**Tech Stack:** `androidx.profileinstaller:profileinstaller:1.4.1`, AGP 9.4 (fusion automatique de `src/main/baseline-prof.txt` en release), JUnit4.

**Spec:** `docs/superpowers/specs/2026-11-24-synxio-6.0-flow-design.md` §3 ; prérequis : étape 2 livrée (`v5.12.0`).
