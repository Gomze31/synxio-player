# Au poignet 5.10.0 — Synxio sur Wear OS

*Version 5.10.0, dédiée à la montre. Reprend la proposition X4 de `docs/AUDIT_EVOLUTION_2026-11.md` (« Module montre : commandes, file, favoris, tuile, complication »), réduite à une première version télécommande. Base : branche `dev-5.5` après la 5.9.0 (spec `2026-11-05-android-auto-5.9.0-design.md`). Date : 19 novembre 2026. Validé par l'utilisateur dans la conversation, section par section. Appareil cible : Galaxy Watch 7 (Wear OS 5, API 34) appairée à un téléphone Android avec Play Services.*

## Objectif

Piloter la lecture du téléphone depuis la montre : voir ce qui joue, lecture/pause, précédent/suivant, cœur, volume à la couronne, lancer les favoris, la lecture aléatoire, la reprise ou « Surprends-moi » sans toucher le téléphone. Une tuile et une complication « en cours » prolongent le lecteur sur le cadran. La montre ne lit aucun fichier elle-même : c'est une télécommande.

## Décisions prises avec l'utilisateur

- **Télécommande seulement.** Pas de lecture autonome sur la montre (transfert de titres, lecteur Media3 sur montre) : hors périmètre, envisageable en V2.
- **Périmètre V1 : lecteur + tuile + complication + lancement rapide.** Pas de file, pas de navigation bibliothèque, pas de seek, pas de bascule aléatoire/répétition sur la montre.
- **Transport : Wearable Data Layer** (Play Services). Écarté : s'appuyer sur les contrôles média système de Wear OS (aucune identité, ni cœur, ni lancement rapide) et un protocole Bluetooth RFCOMM maison (réveil du téléphone non garanti, fragile).
- **Installation : ADB Wi-Fi sur la montre.** Pas de Play Store ; l'APK montre est publié dans la release GitHub comme l'APK téléphone.
- **Sans attendre I7.** L'audit liait X4 au découpage de `PlaybackService`. On ajoute un collaborateur injecté sur le modèle de `WidgetUpdater`, sans refonte du service.

## Constat vérifié dans le code

- `PlaybackService` (`playback/PlaybackService.kt`) est un `MediaLibraryService` Media3 1.11.1, Hilt, qui expose déjà des commandes maison (`CMD_TOGGLE_FAVORITE`, `CMD_TOGGLE_SHUFFLE`, `CMD_CYCLE_REPEAT`, `CMD_SLEEP_TIMER`, `CMD_ALARM_MODE`) aux contrôleurs de confiance dans `LibrarySessionCallback.onConnect`.
- `refreshWidgetSoon()` (`PlaybackService.kt:750`) construit un `WidgetSnapshot` (`widget/WidgetState.kt:21`) après un délai `WIDGET_REFRESH_DELAY_MS` et le confie à `WidgetUpdater.publish(snapshot, artworkUri)` (`widget/WidgetUpdater.kt:57`), qui dédoublonne avec `displaysSameAs`. Le snapshot porte déjà `mediaId`, `title`, `artist`, `album`, `isPlaying`, `positionMs`, `durationMs`, `capturedAtMs`, `shuffle`, `repeatMode`, `favorite`, `hasNext`, `live`, `accent`, `accentLight`, et sait extrapoler la position (`progressAt`).
- `onSetMediaItems` (`PlaybackService.kt:1859`) résout les identifiants `BrowseIds` (`playback/BrowseTree.kt:34-74`) : `synxio://favorites`, `synxio://shuffle/<id>`, `synxio://last-queue`, `synxio://surprise`. Un contrôleur qui pose un `MediaItem` portant un tel `mediaId` obtient la file correspondante.
- Les actions rapides téléphone (`fr.synxio.player.SHUFFLE_ALL`, `PLAY_FAVORITES`, `RESUME`) sont traitées dans `MainActivity.kt:147` côté interface : non réutilisables depuis un service.
- Le manifeste déclare déjà `<package android:name="com.samsung.android.app.watchmanager" />` dans `<queries>` (détection Galaxy Wearable pour les Buds). `play-services-cast-framework` est une dépendance : Play Services sont déjà supposés présents sur le téléphone.
- Signature release : `app/build.gradle.kts:52` lit `keystore.properties` ; `release.yml` rejoue la signature en v3 avec `apksigner` sur `app/build/outputs/apk/release/*.apk` et vérifie un signataire épinglé. `ci.yml` lance `lintDebug` et `assembleDebug` seulement.
- Catalogue : AGP 9.4.1, Kotlin 2.4.21, Compose BOM 2026.09.00, Hilt 2.60.1, KSP 2.3.12, kotlinx-serialization 1.12.0, JUnit 4. Tests unitaires existants dans `app/src/test`, dont `widget/WidgetSnapshotTest.kt`.

## 1. Architecture et protocole

### 1.1 Modules

Trois modules Gradle :

| Module | Rôle |
|---|---|
| `:app` | Inchangé en structure. Nouveau paquet `fr.synxio.player.wear/` : `WearBridge`, `WearCommandService`, `WearStatePublisher`. |
| `:wear-protocol` | Kotlin JVM pur (plugin `org.jetbrains.kotlin.jvm` + `kotlin-serialization`), sans dépendance Android. Constantes de chemins et de clés, modèle `WearState`, parse des commandes `WearCommand`. Dépendance des deux applications. |
| `:wear` | Application Wear OS : Compose for Wear OS Material 3, Tiles (ProtoLayout), Complications, Hilt. |

`settings.gradle.kts` : `include(":app", ":wear", ":wear-protocol")`.

### 1.2 Côté téléphone (`:app`)

- **`WearBridge`** (`@Singleton`, injecté dans `PlaybackService` comme `WidgetUpdater`). `refreshWidgetSoon()` l'appelle juste après `widgetUpdater.publish(snapshot, artworkUri)` avec le même couple. `WearBridge.publish(snapshot, artworkUri, volume)` :
  1. Convertit le `WidgetSnapshot` en `WearState` (voir 1.4) et ajoute `volume` (`AudioManager.getStreamVolume(STREAM_MUSIC) / getStreamMaxVolume`).
  2. Dédoublonne : si le `WearState` précédent est identique hors `capturedAtMs`/`positionMs` et que la position extrapolée de l'ancien est à moins de 2 s de la nouvelle, ne publie pas.
  3. Prépare la pochette en `Asset` seulement si `mediaId` a changé depuis la dernière publication : décodage via Coil, redimensionnement 160 px, JPEG qualité 80, plus un second `Asset` flouté (flou gaussien rayon 24 sur une version 32 px, remontée à 160 px) pour le fond du lecteur. Les deux `Asset` sont conservés en mémoire et réattachés aux publications suivantes du même `mediaId`.
  4. `PutDataMapRequest.create("/synxio/state")`, `setUrgent()`, `DataClient.putDataItem`. Tout `ApiException` (Play Services absents, montre non appairée) est attrapé et journalisé sous `SynxioWear` : le service ne plante jamais pour la montre.
- **`WearStatePublisher`** : interface à une méthode `suspend fun publish(state: WearState, art: ByteArray?, blurredArt: ByteArray?)`, implémentée par `DataLayerStatePublisher` (vrai `DataClient`). `WearBridge` dépend de l'interface (Hilt), ce qui permet de le tester sans Play Services.
- **`WearCommandService : WearableListenerService`**, déclaré dans le manifeste avec `android:exported="true"` et les filtres `com.google.android.gms.wearable.MESSAGE_RECEIVED` (`data android:scheme="wear" android:host="*" android:pathPrefix="/synxio/cmd"`) et `com.google.android.gms.wearable.CAPABILITY_CHANGED`. `onMessageReceived` parse la charge en `WearCommand` ; charge invalide ignorée. Il construit un `MediaController` sur `PlaybackService` (`SessionToken`), ce qui démarre le service s'il est arrêté, attend la connexion 5 s au plus, exécute, puis `MediaController.releaseFuture`. Un `WearCommandService` ne garde aucun contrôleur ouvert entre deux messages.
- **Capacité** : `app/src/main/res/values/wear.xml` déclare `<string-array name="android_wear_capabilities"><item>synxio_phone</item></string-array>`.
- **Dépendance** : `play-services-wearable`.

### 1.3 Côté montre (`:wear`)

- `applicationId = "fr.synxio.player"` : obligatoire, le Data Layer ne relie que des applications de même identifiant et même signature. `minSdk 30`, `targetSdk 34`. `versionCode` et `versionName` identiques à `:app` (5.10.0), lus depuis une propriété partagée dans `gradle.properties` racine (`synxio.versionCode`, `synxio.versionName`) utilisée par les deux modules.
- Manifeste : `<uses-feature android:name="android.hardware.type.watch" />`, `<meta-data android:name="com.google.android.wearable.standalone" android:value="false" />`.
- **`WearStateRepository`** (`@Singleton`) : au démarrage, lit l'état courant par `DataClient.getDataItems(Uri "wear://*/synxio/state")`, puis `addListener`. Expose `StateFlow<WearState?>` et `StateFlow<Connectivity>` (`PHONE_REACHABLE`, `PHONE_UNREACHABLE`, `PLAY_SERVICES_MISSING`). La joignabilité vient de `CapabilityClient.getCapability("synxio_phone", FILTER_REACHABLE)` et de son listener. Pas de polling.
- **`WearCommandSender`** : `MessageClient.sendMessage(nodeId, "/synxio/cmd", payload)` vers le premier nœud joignable `synxio_phone`. Résultat exposé en `Result<Unit>` ; échec → toast « Téléphone injoignable ».
- **`WearStateListener : WearableListenerService`** (montre) : filtre `DATA_CHANGED` sur `/synxio/state`. À chaque changement : `TileService.getUpdater(context).requestUpdate(SynxioTileService::class.java)` et `ComplicationDataSourceUpdateRequester.create(context, ComponentName(NowPlayingComplicationService)).requestUpdateAll()`. Il ne touche pas à l'UI Compose, qui a son propre listener via `WearStateRepository`.
- Vérification `GoogleApiAvailability.isGooglePlayServicesAvailable` au démarrage de l'activité : échec → écran « Play Services requis ».

### 1.4 Protocole (`:wear-protocol`)

```kotlin
object WearPaths {
    const val STATE = "/synxio/state"
    const val COMMAND = "/synxio/cmd"
    const val CAPABILITY_PHONE = "synxio_phone"
    const val PROTOCOL_VERSION = 1
}

@Serializable
data class WearState(
    val protocolVersion: Int = WearPaths.PROTOCOL_VERSION,
    val mediaId: String = "",
    val title: String = "",
    val artist: String = "",
    val isPlaying: Boolean = false,
    val favorite: Boolean = false,
    val positionMs: Long = 0L,
    val durationMs: Long = 0L,
    val capturedAtMs: Long = 0L,
    val live: Boolean = false,
    val hasNext: Boolean = false,
    val shuffle: Boolean = false,
    val repeatMode: Int = 0,
    val volume: Float = 0f,          // 0..1
    val accent: Int = 0,             // ARGB, 0 = absent
    val accentLight: Int = 0,
) {
    val isEmpty: Boolean get() = mediaId.isEmpty()
    /** Position extrapolée. Un état « en lecture » plus vieux que [STALE_MS] est traité comme en pause. */
    fun progressAt(nowMs: Long): Long
    fun isStaleAt(nowMs: Long): Boolean = isPlaying && nowMs - capturedAtMs > STALE_MS
    companion object { const val STALE_MS = 6 * 60 * 60 * 1000L }
}

sealed interface WearCommand {
    data object PlayPause : WearCommand
    data object Next : WearCommand
    data object Previous : WearCommand
    data object ToggleFavorite : WearCommand
    data object VolumeUp : WearCommand
    data object VolumeDown : WearCommand
    data class Volume(val level: Float) : WearCommand   // 0..1
    data class Seek(val positionMs: Long) : WearCommand
    data class Start(val mediaId: String) : WearCommand

    fun encode(): String
    companion object { fun parse(payload: String): WearCommand? }
}
```

Encodage des commandes, une chaîne UTF-8 : `play_pause`, `next`, `previous`, `toggle_favorite`, `volume_up`, `volume_down`, `volume:<0..1>`, `seek:<ms>`, `start:<mediaId>`. `parse` renvoie `null` pour toute chaîne inconnue, un niveau hors `[0, 1]` ou une position négative.

Le `DataItem` `/synxio/state` porte dans sa `DataMap` : `state` (JSON de `WearState` via kotlinx.serialization), `art` (`Asset`, optionnel), `artBlurred` (`Asset`, optionnel). Les `Asset` sont omis quand aucune pochette n'est disponible ; la montre garde alors son fond encre.

Identifiants acceptés par `Start` en V1 : `synxio://last-queue`, `synxio://favorites`, `synxio://shuffle/all`, `synxio://surprise`. Le téléphone transmet tel quel à `onSetMediaItems`, qui sait déjà les résoudre ; un identifiant inconnu produit une file vide et aucune lecture, sans erreur.

### 1.5 Exécution des commandes sur le téléphone

| Commande | Action dans `WearCommandService` |
|---|---|
| `PlayPause` | Service déjà en lecture ou en pause avec une file : `Util.handlePlayPauseButtonAction(controller)`. File vide (`mediaItemCount == 0`) : équivaut à `Start("synxio://last-queue")`. |
| `Next` / `Previous` | `seekToNext()` / `seekToPrevious()`. |
| `ToggleFavorite` | `sendCustomCommand(SessionCommand(CMD_TOGGLE_FAVORITE), Bundle.EMPTY)`. |
| `VolumeUp` / `VolumeDown` | `AudioManager.adjustStreamVolume(STREAM_MUSIC, ADJUST_RAISE / ADJUST_LOWER, FLAG_SHOW_UI)`, puis republication immédiate de l'état (appel de `WearBridge.publishVolumeOnly()`, qui réémet le dernier `WearState` avec le nouveau `volume`). |
| `Volume(level)` | `setStreamVolume(STREAM_MUSIC, round(level * max), FLAG_SHOW_UI)`, même republication. Non utilisé par l'UI V1. |
| `Seek(ms)` | `seekTo(ms)`. Non utilisé par l'UI V1. |
| `Start(id)` | `setMediaItem(MediaItem.Builder().setMediaId(id).build())`, `prepare()`, `play()`. |

Le `WearCommandService` ne connaît pas `PlaybackService` autrement que par `MediaController` : il est traité comme Android Auto, un contrôleur externe de confiance (même paquet, même signature, donc `onConnect` lui accorde les commandes maison).

### 1.6 Position, progression, volume

- La montre ne reçoit pas de tick. Elle extrapole la position avec `WearState.progressAt(now)` tant que `isPlaying`, et fige l'anneau sinon. Le téléphone republie à chaque transition (piste, lecture/pause, seek, favori, volume) via `refreshWidgetSoon()`, qui absorbe déjà les rafales par son délai.
- Couronne : un cran = `VolumeUp` ou `VolumeDown`. Pas de `Volume(level)` continu depuis l'UI, pour éviter les rafales. Côté montre, les crans sont `conflate`-és sur 80 ms. Le téléphone n'a pas de garde.

## 2. Écrans montre, tuile, complication

### 2.1 Identité

Lumen transposé à la montre : fond encre `#0C0A10` en permanence (OLED, ambiant), accent = `WearState.accent` (couleur dominante de la pochette, calculée par le téléphone), repli sur la braise Lumen si `accent == 0`. Police système Wear (pas de Google Fonts sur montre). `MaterialTheme` Wear M3 avec un `ColorScheme` recoloré : `primary = accent`, `onPrimary` choisi par contraste, `surface`/`background = encre`. Les animations respectent `Settings.Global.ANIMATOR_DURATION_SCALE` (réduction des animations système).

### 2.2 Navigation

`SwipeDismissableNavHost` avec deux destinations horizontales : `player` (accueil) et `launch`. Balayage gauche depuis `player` → `launch` ; balayage droit depuis `launch` → retour ; balayage droit depuis `player` → fermer (comportement système). Quand `Connectivity != PHONE_REACHABLE` ou `WearState.isEmpty`, la destination `player` affiche `DisconnectedScreen` à la place du lecteur ; `launch` reste accessible.

### 2.3 Écran lecteur (`PlayerScreen`)

- Fond : `Asset artBlurred` affiché plein écran, voile encre à 60 %. Sans `Asset` : encre pleine.
- Centre : pochette ronde 56 dp (`Asset art`) entourée d'un `CircularProgressIndicator` M3 (piste fine, couleur accent) dont la valeur est `progressAt(now) / durationMs`, rafraîchie chaque seconde quand `isPlaying` et visible. Masqué si `live` ou `durationMs == 0`. Si `isStaleAt(now)`, l'état est affiché en pause.
- Titre (1 ligne, défilement si tronqué) et artiste (1 ligne, atténué).
- Rangée de commandes : précédent · lecture/pause (`IconButton` plein, accent, 52 dp) · suivant. `hasNext == false` grise suivant. Chaque appui envoie la commande et bascule l'icône de façon optimiste jusqu'au prochain état (délai max 3 s, puis retour à l'état reçu).
- Cœur sous la rangée : plein si `favorite`. À la bascule : animation de battement (échelle 1 → 1,25 → 1 sur 250 ms) et retour haptique.
- Couronne : volume. Un arc de volume (droite de l'écran) apparaît 1,5 s après chaque cran, valeur = `WearState.volume` avec bascule optimiste par pas de `1/15`.
- Pas de barre de progression manipulable.

### 2.4 Écran lancer (`LaunchScreen`)

`ScalingLazyColumn` de quatre `Chip` pleine largeur, icône + libellé, dans l'ordre : **Reprendre** (`synxio://last-queue`), **Favoris** (`synxio://favorites`), **Aléatoire** (`synxio://shuffle/all`), **Surprends-moi** (`synxio://surprise`). Un appui envoie `Start(id)`, revient sur `player` qui affiche « Connexion… » (indicateur indéterminé) jusqu'au prochain `WearState` non vide ; passé 8 s, toast « Téléphone injoignable » et retour à l'affichage précédent.

### 2.5 Écran déconnecté (`DisconnectedScreen`)

| Situation | Contenu |
|---|---|
| Nœud joignable, état vide ou absent | Logo, « Synxio est en pause sur le téléphone », bouton **Reprendre** (= `Start("synxio://last-queue")`). |
| Aucun nœud `synxio_phone` joignable | Logo, « Téléphone hors de portée ». Pas de bouton. |
| `protocolVersion` reçu > `PROTOCOL_VERSION` de la montre, ou l'inverse | « Mets à jour Synxio sur le téléphone » ou « … sur la montre ». |
| Play Services absents | « Play Services requis ». |

### 2.6 Tuile (`SynxioTileService`)

ProtoLayout Material 3.

- Lecture en cours : pochette (image de l'`Asset art` en ressource inline, 48 dp), titre, artiste, trois boutons `lecture/pause · suivant · cœur`. Chaque bouton est une `LoadAction` ; `onTileRequest` lit `state.lastClickableId`, envoie la commande correspondante via `WearCommandSender`, puis renvoie la tuile avec l'état optimiste. Appui sur la pochette : `LaunchAction` vers `MainActivity` de la montre.
- Rien en cours ou déconnecté : titre « Synxio », deux boutons **Reprendre** · **Favoris** (`Start`).
- `setFreshnessIntervalMillis(0)` : la tuile est rafraîchie uniquement par `WearStateListener` (événement), jamais par horloge.
- Ressources : `onTileResourcesRequest` fournit l'icône de l'appli et la pochette courante (bytes de l'`Asset`), identifiées par `mediaId` pour que la montre ne redécode pas inutilement.

### 2.7 Complication (`NowPlayingComplicationService`)

Types déclarés : `SHORT_TEXT`, `LONG_TEXT`, `SMALL_IMAGE`.

| Type | Lecture en cours | Rien en cours |
|---|---|---|
| `SHORT_TEXT` | Titre tronqué (7 caractères), icône note monochrome | « Synxio », icône note |
| `LONG_TEXT` | « Titre — Artiste » | « Synxio » |
| `SMALL_IMAGE` | Pochette (`Asset art`, type `PHOTO`) | Icône de l'appli |

Appui : `PendingIntent` vers `MainActivity` de la montre. Mise à jour par `WearStateListener` via `requestUpdateAll()`. `getPreviewData` renvoie un exemple « Clair de lune — Debussy ».

### 2.8 Ambiant

`AmbientLifecycleObserver` sur l'activité. En ambiant : `PlayerScreen` passe en version plate (pas de fond pochette, texte blanc à 70 %, anneau figé, boutons masqués) et cesse de rafraîchir l'anneau. Sortie d'ambiant : retour à la version complète et relecture immédiate de l'état.

### 2.9 Hors périmètre V1

File, navigation bibliothèque, seek, bascule aléatoire/répétition, lecture autonome, Buds reliés à la montre. Les champs `shuffle`, `repeatMode`, `Seek`, `Volume(level)` sont dans le protocole pour une V2 sans rupture de version.

## 3. Erreurs, tests, build, livraison

### 3.1 Erreurs et cas limites

- **Téléphone absent** : aucun nœud `synxio_phone` → écran déconnecté « hors de portée ». Nœud présent mais `sendMessage` rejette → toast « Téléphone injoignable », état inchangé.
- **Service téléphone arrêté** : toute commande ouvre un `MediaController`, ce qui démarre `PlaybackService`. `Start` et `PlayPause` sur file vide lancent une lecture ; `Next`, `Previous`, `ToggleFavorite`, `Seek` sur file vide ne font rien. Connexion non établie en 5 s : commande abandonnée, journal `SynxioWear`.
- **Play Services absents** : montre → écran « Play Services requis » ; téléphone → `WearBridge` attrape `ApiException`, journalise, le service continue.
- **Pochette** : `Asset` toujours recompressé 160 px JPEG qualité 80 (ordre de 10 Ko). Décodage en échec → état publié sans `Asset`, la montre garde le fond encre et la pochette précédente disparaît (clé `mediaId` différente).
- **État périmé** : `isStaleAt(now)` (en lecture depuis plus de 6 h sans republication, typiquement un téléphone redémarré) → affiché en pause, anneau figé.
- **Rafales** : couronne `conflate` 80 ms côté montre ; `refreshWidgetSoon()` absorbe les transitions côté téléphone ; `WearBridge` dédoublonne avant publication.
- **Version de protocole** : `protocolVersion` dans l'état ; écart → message de mise à jour (2.5), commandes toujours envoyées (compatibilité ascendante des chaînes).
- **Permissions** : aucune nouvelle. Le Data Layer passe par Play Services, pas par `BLUETOOTH_CONNECT`.

### 3.4 Installation Watch 7

Documentée dans `README.md`, section « Montre (Wear OS) » :

1. Sur la montre : Paramètres → À propos de la montre → Logiciel → sept appuis sur « Version du logiciel » ; Options de développeur → Débogage ADB et Débogage via Wi-Fi activés. La montre affiche son adresse IP.
2. Sur le PC : `adb connect <ip-montre>:5555`, accepter l'invite sur la montre.
3. `adb -s <ip-montre>:5555 install -r wear-release.apk`.
4. Installer la même version de `app-release.apk` sur le téléphone. Versions différentes → la montre affiche le message de mise à jour (2.5).
